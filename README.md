# המכלול אופליין - Hamichlol Offline

אפליקציית Electron המאפשרת התקנת והרצת MediaWiki באופן מקומי ללא צורך בחיבור לאינטרנט.

## מאפיינים

- שימוש ב-PHP, MariaDB/MySQL ו-MediaWiki שכבר מותקנים במחשב
- הורדה והתקנה אוטומטית של מה שחסר (PHP ו-MariaDB: ב-Windows בלבד)
- ממשק משתמש פשוט לניהול השרתים, ותפריט עברי מלא
- הוויקי מוצג בכל חלון האפליקציה, ומותקן בעברית
- הרצת המערכת ללא צורך בחיבור לאינטרנט

## דרישות מערכת

- Windows 10 ומעלה, או לינוקס / macOS עם PHP ו-MariaDB (או MySQL) מותקנים
- מינימום 500MB פנויים בדיסק
- מינימום 4GB RAM

## התקנה למפתחים

1. התקן את Node.js בגרסה 22.12 ומעלה (דרישה של Electron)
2. שבט (Clone) את המאגר:
```bash
git clone https://github.com/michi-tz/hamichlol-offline.git
cd hamichlol-offline
```

3. התקן את התלויות:
```bash
npm install
```

4. הרץ את האפליקציה:
```bash
npm start
```

## בנייה לשימוש

```bash
npm run dist
```

הקובץ המותקן יהיה זמין בתיקיית `dist`.

## ממשק המשתמש

לחלון יש שני מצבים:

- **מסך ההתקנה** (כשהשרתים כבויים): שלושה שלבים עם מחוון התקדמות - התקנת השרתים, הגדרת הוויקי והפעלה.
  בזמן פעולה ארוכה (הורדה, התקנה, הפעלה) מוצג מצב "עובד", ושגיאות מוצגות בנפרד משורת המצב הרגילה.
  אחרי הפעלה מחדש של האפליקציה המסך ממשיך מהשלב שבו עצר.
- **מצב ויקי** (כשהשרתים פועלים): הוויקי ממלא את כל החלון. מעליו נשאר רק סרגל דק עם ניווט
  (אחורה, קדימה, רענון, עמוד ראשי), נורית "השרתים פועלים", פתיחה בדפדפן חיצוני וכפתור לעצירת השרתים.
  אם השרתים נעצרים מעצמם, החלון חוזר למסך ההתקנה ומציג הודעה. כשהסנכרון עם האתר חסום (עדכון הגדרות שנכשל),
  הנורית מציגה זאת כאזהרה, ולא כשגיאה: הוויקי עצמו פועל.

הוויקי מוצג ב-`WebContentsView` נפרד (ולא ב-`iframe` בתוך דף האפליקציה): בלי גישה ל-Node, בארגז חול (sandbox),
עם עוגיות נפרדות, ובלי הרשאות (מצלמה, מיקום וכו'). כך גם דפי העריכה של MediaWiki, שאסור להציג במסגרת, עובדים.
רק כתובות של הוויקי המקומי (`127.0.0.1` / `localhost` בפורט של PHP) נפתחות בתוך האפליקציה;
קישורים לאתרים אחרים, וגם קישורים שמבקשים חלון חדש, נפתחים בדפדפן של המערכת.

התפריט:

| תפריט | פקודות |
|-------|--------|
| שרתים | הפעל שרתים, עצור שרתים, הפעל מחדש, שדרוג MediaWiki, ניסיון חוזר לעדכן את הגדרות הוויקי (רק אחרי שהעדכון נכשל), יציאה (כל פקודה זמינה רק כשאפשר לבצע אותה) |
| ויקי | עמוד ראשי, אחורה, קדימה, רענון, פתח בדפדפן חיצוני (זמין רק כשהוויקי מוצג) |
| סנכרון | מקום שמור לסנכרון עם אתר המכלול, שעדיין לא קיים |
| תצוגה | הגדלה, הקטנה וגודל רגיל (של הוויקי כשהוא מוצג), מסך מלא, כלי פיתוח |
| עריכה | ביטול, ביצוע שוב, גזירה, העתקה, הדבקה, בחירת הכול |
| עזרה | אודות, פתיחת תיקיית הנתונים |

הכפתורים בחלון והפקודות בתפריט מפעילים את אותו קוד בתהליך הראשי, ולכן תמיד מסונכרנים.

## הגדרת הוויקי

הוויקי מותקן בעברית (`install.php --lang=he`, כלומר `$wgLanguageCode = "he"`). שפה של ויקי שכבר הותקן בעבר אינה משתנה.

שם המשתמש והסיסמה של המנהל נבדקים כבר בטופס, תוך כדי הקלדה, לפי אותם כללים ש-MediaWiki 1.46
מחיל על מנהלים (`$wgPasswordPolicy` לקבוצות sysop, ‏bureaucrat ו-interface-admin) - כך שתוכנית ההתקנה
לא נכשלת באמצע, אחרי שמסד הנתונים כבר נוצר:

- לפחות 10 תווים ועד 4096. האורך נמדד בבתים, כמו ב-MediaWiki, ולכן אות עברית נספרת כשניים
- הסיסמה אינה מוכלת בשם המשתמש (בלי הבדל בין אותיות גדולות לקטנות)
- הסיסמה אינה אחת מסיסמאות הדוגמה ש-MediaWiki חוסם (למשל `ExamplePassword`)
- הסיסמה אינה ברשימת הסיסמאות הנפוצות של MediaWiki (הספרייה `wikimedia/common-passwords`, שנקראת מתיקיית
  `vendor` של ה-MediaWiki שהורד; אם הקובץ חסר או בפורמט לא מוכר, רק הבדיקה הזו מדולגת)
- שם המשתמש תקין: בלי התווים `# < > [ ] | { } / @ : =`, לא כתובת IP, לא שם שמור, לא ארוך מדי.
  האות הראשונה של השם הופכת לגדולה, וקו תחתון הופך לרווח - הטופס מציג איך השם יישמר

אם בכל זאת תוכנית ההתקנה נכשלת, מוצגת הודעה עם פרטי השגיאה (בלי הסיסמאות), ואפשר לתקן את הטופס ולנסות שוב:
מסד הנתונים של הניסיון הקודם נמחק ונוצר מחדש.

### הרחבות והגדרות האתר

כדי שדף שיובא מאתר המכלול ייראה כמו באתר, האפליקציה מפעילה את ההרחבות שהאתר משתמש בהן, מתוך אלה שכלולות
בחבילת MediaWiki עצמה (שום הרחבה לא יורדת ממקום אחר), ואת ההגדרות של האתר שמשפיעות על ייבוא ועל תצוגה.

הכול נמצא בקובץ אחד שהאפליקציה מנהלת: `HamichlolSettings.php` בתיקיית MediaWiki (נוצר ב-`src/wiki-settings.js`).
`LocalSettings.php` שייך למשתמש: האפליקציה רק מוסיפה בסופו, פעם אחת, שורה שטוענת את הקובץ, ולא משנה בו דבר אחר
(חוץ מהוצאת השורה הזו כשהעדכון הראשון של ההגדרות נכשל, ראו בהמשך).

- הקובץ נכתב מחדש בהתקנה, בשדרוג ובכל הפעלה של השרתים (אלא אם עדכון של התוכן הזה נכשל, ראו בהמשך), כך שגרסה חדשה של האפליקציה יכולה לשנות אותו. שינויים ידניים בו הולכים לאיבוד
- כדי לשנות הגדרה, כותבים אותה שוב ב-`LocalSettings.php` אחרי שורת הטעינה
- כדי לכבות את כל ההגדרות של האפליקציה, הופכים את שורת הטעינה להערה (`#`). כל עוד שם הקובץ מופיע ב-`LocalSettings.php`, השורה לא תתווסף שוב
- נטען רק מה שקיים בתיקיית MediaWiki, כך שוויקי מגרסה ישנה (למשל 1.43, בלי TemplateStyles) ממשיך לעבוד

ההרחבות שמופעלות:

| מטרה | הרחבות |
|------|--------|
| תצוגת דפים, תבניות ויחידות | ParserFunctions, ‏Scribunto, ‏Cite, ‏TemplateStyles, ‏TemplateData, ‏CategoryTree, ‏ImageMap, ‏InputBox, ‏Poem, ‏Math, ‏SyntaxHighlight, ‏Gadgets, ‏PageImages, ‏MultimediaViewer |
| עריכה | WikiEditor, ‏CodeEditor, ‏VisualEditor |

הרחבות שקיימות באתר ובחבילה אבל אינן מופעלות: AbuseFilter, ‏CheckUser, ‏ConfirmEdit ו-Nuke (הגנה מפני משתמשים אחרים, שאין בעותק
אישי), Echo, ‏Thanks ו-DiscussionTools (התראות ודפי שיחה של ויקי משותף; ההודעות מהאתר יגיעו מהאתר עצמו), Linter, ‏ReplaceText
(החלפה גורפת שהופכת דפים מיובאים לעריכות מקומיות), TextExtracts (אין מי שקורא את התקצירים) ו-PdfHandler (דורש תוכנות חיצוניות).
רובן גם מוסיפות טבלאות למסד הנתונים.

כל ההרחבות עובדות בלי רשת:

- **Scribunto** מריץ את מפרש Lua שמגיע עם ההרחבה (Windows ‏x86/x64, לינוקס x86/x64, ‏macOS ‏x86_64; ב-Mac עם מעבד Apple דרוש Rosetta 2,
  ובלינוקס על ARM אין מפרש מתאים). חילוץ ה-zip מאבד את הרשאת ההרצה שלו, והאפליקציה מחזירה אותה. מגבלות הזמן והזיכרון
  גבוהות מאלה של האתר (30 שניות, ‏100MB), כי המפרש הזה איטי מ-LuaSandbox שבאתר.
  ב-Windows ‏Scribunto עוטף את הפקודה שמפעילה את המפרש בזוג מירכאות נוסף, ש-PHP 8 כבר מוסיף בעצמו, ו-`cmd.exe` לא מוצא
  את המפרש ("The interpreter exited with status 1"). האפליקציה מוחקת את השורה הזו בעותק שלה של Scribunto, רק כשהיא בדיוק
  כמו בגרסה שפורסמה (ראו [הדיון ב-mediawiki.org](https://www.mediawiki.org/wiki/Topic:W6pj4xql1tjpvfyb))
- **Math** מציג נוסחאות כ-MathML שנוצר ב-PHP (מצב `native`), בלי שירות חיצוני
- **SyntaxHighlight** מריץ את Pygments שמגיע עם ההרחבה, ודורש `python3` במחשב. בלי Python (למשל ב-Windows) הקוד מוצג כטקסט רגיל, בלי שגיאה בדף
- **VisualEditor** מריץ את Parsoid בתוך MediaWiki
- `$wgUseInstantCommons` ו-`$wgPingback` כבויים

הגדרות האתר:

- **מרחבי שם** כמו באתר, כדי שדפים מיובאים יגיעו למרחב הנכון: טיוטה (3000), פורטל (4000) ותיקון (5000) עם דפי השיחה שלהם, וכל
  הכינויים של האתר (למשל `תב:`, `מכ:`, `פ:`). דפים של מרחבים מעל 100 מיובאים לפי השם, ולכן בלי ההגדרה הם היו נוחתים במרחב הראשי
- **מרחב 4** נקרא "המכלול", כמו באתר, כדי שקישורים כמו `[[המכלול:...]]` בתוכן יעבדו. שם האתר שנבחר בהתקנה לא משתנה,
  והשם הקודם של מרחב 4 (שנגזר משם האתר) נשאר ככינוי, כך שקישורים לדפי המיזם של הוויקי עצמו ממשיכים לעבוד
- אזור זמן `Asia/Jerusalem`, קישורים חיצוניים בלשונית חדשה, דפים עד 30,000KB (בברירת המחדל, 2,048KB, ייבוא של דף ארוך יותר נכשל),
  הפניות רספונסיביות, וגדלי התמונות הממוזערות של האתר. פונקציות המחרוזת של ParserFunctions (`{{#len:}}` וכו') כבויות, כמו באתר

הרחבות שמוסיפות טבלאות דורשות את `update.php`. בהפעלת השרתים האפליקציה מריצה אותו, לפני ש-PHP (הוויקי) מופעל, כשתוכן `HamichlolSettings.php`
השתנה מאז ההרצה המוצלחת האחרונה (נרשם ב-`HamichlolSettings.schema.json`) - בפועל, אחרי עדכון של האפליקציה - ובשדרוג כחלק מהשדרוג עצמו.

לפני ההרצה האפליקציה שומרת את מה שצריך כדי לחזור אחורה: עותק של מסד הנתונים (`database.settings-backup`, נלקח כששרת מסד הנתונים
עדיין כבוי, לפני שהוא מופעל) ואת הקבצים הקודמים (`HamichlolSettings.php`, ‏`HamichlolSettings.schema.json` ו-`LocalSettings.php`), ביומן
`wiki-settings-update.json` בתיקיית הנתונים. אם העדכון הצליח, העותק נמחק. אם הוא נכשל:

- הוויקי מוחזר למצבו שלפני העדכון - מסד הנתונים מהעותק וההגדרות הקודמות - **ומופעל כרגיל** במצב הזה
- מוצגת הודעה (בסרגל שמעל הוויקי ובמסך ההפעלה) שהעדכון נכשל, שהוויקי הוחזר למצבו הקודם ושהסנכרון עם אתר המכלול חסום עד שהעדכון יצליח.
  הכישלון נשמר ב-`HamichlolSettings.failed.json` בתיקיית MediaWiki, ולכן ההודעה נשארת גם אחרי סגירה ופתיחה של האפליקציה
- העדכון לא ינוסה שוב בכל הפעלה (כדי שעדכון שנכשל תמיד לא יעלה בכל פתיחה של האפליקציה בהעתקה של מסד הנתונים ובניסיון כושל),
  אלא כשתוכן ההגדרות משתנה (גרסה חדשה של האפליקציה או של MediaWiki), או כשהמשתמש מבקש: "נסה שוב" במסך ההפעלה, או
  "נסה שוב לעדכן את הגדרות הוויקי" בתפריט "שרתים". שדרוג MediaWiki שהצליח מבטל גם הוא את החסימה, כי `update.php` שלו כבר כולל את ההגדרות

"המצב הקודם" של ויקי שעדיין לא עבר אף עדכון מוצלח של ההגדרות - ויקי שהותקן זה עתה, או ויקי מגרסה של האפליקציה שלא היה בה
`HamichlolSettings.php` - הוא הוויקי בלי הגדרות האפליקציה: בלי הקובץ ובלי השורה שטוענת אותו ב-`LocalSettings.php` (אם המשתמש
שינה את השורה הזו, היא והקובץ נשארים כמו שהם).

אם האפליקציה נסגרה או קרסה באמצע העדכון או באמצע ההחזרה, ההחזרה מושלמת בהפעלה הבאה, לפני שהוויקי מופעל, והעדכון נחשב ככושל.
אם ההחזרה עצמה נכשלת (למשל קובץ נעול), הוויקי לא מופעל, מוצגת הודעת שגיאה, וההחזרה מושלמת בהפעלה הבאה של השרתים.

העותק של מסד הנתונים תופס, לזמן העדכון, מקום בדיסק כגודל תיקיית `database`, וההעתקה נמשכת בהתאם.

## שימוש בתוכנות שכבר מותקנות במחשב

לפני הורדה, האפליקציה מחפשת במחשב PHP, שרת מסד נתונים (MariaDB או MySQL) ו-MediaWiki.
מה שנמצא ומתאים משמש כמות שהוא, ורק מה שחסר יורד. שלב 1 בממשק מציג מה נמצא ומאיפה.

| רכיב | דרישות | מה נעשה איתו |
|------|--------|---------------|
| PHP | גרסה 8.3 בלבד (CLI) עם ההרחבות mysqli, intl, mbstring, fileinfo, openssl, xml, xmlreader, dom, ctype, iconv, json | מורץ ישירות, עם קובץ ה-`php.ini` שלו |
| MariaDB / MySQL | MariaDB 10.3 ומעלה (כולל `mariadb-install-db`) או MySQL 5.7.6 ומעלה | רק התוכנה משותפת: האפליקציה מריצה תהליך משלה, בפורט משלה ועם תיקיית נתונים משלה. שרת שכבר פועל במחשב והנתונים שלו אינם מושפעים |
| MediaWiki | גרסה 1.46 בלבד (הענף של אתר המכלול, כל גרסת תיקונים שלו) | מועתק לתיקיית הנתונים של האפליקציה, בלי `LocalSettings.php`, ‏`images` ו-`cache`. ההתקנה הקיימת אינה משתנה. גרסה מענף אחר לא תשמש: במקומה תורד הגרסה של האפליקציה, ושלב 1 מציג למה ההתקנה שנמצאה לא נבחרה |

החיפוש נעשה ב-`PATH` ובתיקיות התקנה נפוצות (למשל XAMPP, WampServer, Laragon ו-`Program Files` ב-Windows;‏ `/usr/bin`, ‏`/usr/sbin`, ‏`/usr/share/mediawiki` ו-Homebrew במערכות אחרות).
רכיב שהאפליקציה כבר הורידה בעבר ממשיך לשמש גם אם הותקנה בינתיים גרסה במחשב. חריג אחד: קבצי MediaWiki
מענף ישן שעדיין לא הותקן בהם ויקי מוחלפים בגרסה של האפליקציה (ויקי שכבר הותקן משודרג, ראו "שדרוג ויקי מותקן").

משתני סביבה:

| משתנה | תפקיד |
|-------|-------|
| `HAMICHLOL_PHP` | נתיב מלא לקובץ ההרצה של PHP |
| `HAMICHLOL_MYSQLD` | נתיב מלא ל-`mariadbd` / `mysqld` |
| `HAMICHLOL_MEDIAWIKI_DIR` | תיקיית MediaWiki קיימת |
| `HAMICHLOL_USE_SYSTEM=false` | לא להשתמש בתוכנות מותקנות, תמיד להוריד |

הורדה אוטומטית של PHP ו-MariaDB קיימת רק ל-Windows. בלינוקס וב-macOS צריך להתקין אותם מראש,
למשל באובונטו:

```bash
sudo apt install php-cli php-mysql php-intl php-mbstring php-xml mariadb-server
```

שימו לב: אם מסד הנתונים נוצר עם שרת בגרסה אחת, ובהמשך השרת המותקן במחשב מוחלף בגרסה ישנה יותר,
ייתכן שהשרת לא יצליח לפתוח את הנתונים.

## היכן נשמרים הנתונים

השרתים, קבצי MediaWiki ומסד הנתונים נשמרים בתיקיית נתוני המשתמש של האפליקציה
(`%APPDATA%\hamichlol-offline\data` בחלונות), ולא בתיקיית ההתקנה, שבדרך כלל אינה ניתנת לכתיבה.
אפשר לשנות את המיקום באמצעות משתנה הסביבה `HAMICHLOL_DATA_DIR`.

```
data/
├── server/
│   ├── php-<גרסה>/        # PHP
│   └── mariadb-<גרסה>/    # MariaDB
├── database/              # קבצי מסד הנתונים (נפרד מהגרסה של MariaDB)
├── mediawiki/             # MediaWiki, ‏LocalSettings.php ו-HamichlolSettings.php
├── run-state.json         # תהליכי השרתים שרצים כרגע
├── php-update-check.json  # מתי נבדקה לאחרונה גרסה חדשה של PHP
├── mediawiki-upgrade.json # רק בזמן שדרוג MediaWiki (ראו "שדרוג ויקי מותקן")
└── wiki-settings-update.json # רק בזמן עדכון ההגדרות של האפליקציה (ראו "הרחבות והגדרות האתר")
```

השרתים מאזינים רק לכתובת `127.0.0.1`. הפורטים נבחרים מחדש בכל הפעלה,
ו-`LocalSettings.php` מותאם כך שימשיך לעבוד גם אם הפורטים משתנים.

כשהאפליקציה נפתחת מחדש היא ממשיכה מהשלב שבו עצרה. אם בהפעלה קודמת היא קרסה
והשאירה שרתים פועלים, הם נעצרים אוטומטית.

## גרסאות ועדכוני אבטחה

הגרסאות וקישורי ההורדה מוגדרים בקובץ אחד: `src/versions.js`.
כרגע: PHP 8.3, ‏MariaDB 11.8 LTS, ‏MediaWiki 1.46.

גרסת MediaWiki היא זו שאתר המכלול מריץ, כדי שהדפים, התבניות והיחידות יתנהגו כמו באתר. 1.46 אינה גרסת LTS,
ולכן כשהאתר משדרג, מעדכנים גם את `MEDIAWIKI_VERSION`. MediaWiki 1.46 דורש PHP 8.3.0 ומעלה.

גרסת ה-PHP צמודה לענף שוויקימדיה מריצה באתרים שלה, כדי שהוויקי ירוץ על אותו PHP שהקוד של מדיה־ויקי
נבדק עליו בפועל. לכן PHP שמותקן במחשב משמש רק אם הוא מאותו ענף (כרגע 8.3); גרסה ישנה או חדשה יותר
לא תשמש, וב-Windows תורד במקומה הגרסה המתאימה. כשוויקימדיה עוברת לענף חדש, מעדכנים את `PHP_VERSION`.

רק הענף של PHP קבוע, לא גרסת התיקון: תיקוני האבטחה של PHP יוצאים כגרסאות תיקון, ולכן ב-Windows האפליקציה
מורידה את הגרסה החדשה ביותר של הענף לפי [רשימת הגרסאות של windows.php.net](https://windows.php.net/downloads/releases/releases.json),
ובודקת את הקובץ מול סכום ה-SHA-256 שברשימה. הסכום מגיע מאותו אתר כמו הקובץ, כך שהוא מגן מפני הורדה פגומה
ולא מפני אתר שנפרץ. `PHP_VERSION` היא הגרסה הוותיקה ביותר שמורדת, והיא שמורדת כשאי אפשר לקרוא את הרשימה
או שמשהו בה לא נראה כמצופה. גרסה ישנה יותר שכבר הורדה ממשיכה לרוץ עד שגרסה חדשה מחליפה אותה.

לעדכון גרסה: משנים את מספר הגרסה בקובץ ובודקים שהקישורים זמינים:

```bash
npm run check-downloads
```

PHP ו-MariaDB מותקנים בתיקיות לפי גרסה, כך שגרסה חדשה תורד בהפעלה הבאה
לצד הישנה, ומסד הנתונים נשמר.

גם PHP שכבר הורד מתעדכן מעצמו. אחרי שהשרתים עולים, ולכל היותר פעם ביום, האפליקציה בודקת ברשימת הגרסאות
אם יצאה גרסת תיקון חדשה יותר של הענף, ומורידה אותה לצד הגרסה שבשימוש. ההפעלה לא מחכה לבדיקה, ובלי אינטרנט
שום דבר לא משתנה. הגרסה החדשה רצה מההפעלה הבאה, והישנה נמחקת רק אחרי שהחדשה הגישה את הוויקי. אם הגרסה
החדשה לא עולה, היא מועברת הצידה (`php-<גרסה>.failed`) ולא מורדת שוב, והוויקי עולה עם הגרסה הקודמת.

### שדרוג ויקי מותקן

ויקי שהותקן עם גרסת MediaWiki ישנה מזו של האפליקציה ממשיך לעבוד כמו שהוא, ובמסך ההפעלה (ובתפריט "שרתים")
מוצעת האפשרות לשדרג אותו. אם השרתים פועלים, הם נעצרים לזמן השדרוג ומופעלים שוב בסופו. השדרוג:

1. מוריד את הגרסה החדשה לתיקייה נפרדת (`mediawiki.upgrade-new`), בלי לגעת בוויקי
2. מעביר אליה את מה ששייך לוויקי: `LocalSettings.php` והתיקייה `images` (הקבצים שהועלו, כקישורים קשיחים
   כשאפשר, כך שאינם תופסים מקום נוסף). ההרחבות והעיצובים באים מהגרסה החדשה, והתיקייה `cache` נבנית מחדש.
   `HamichlolSettings.php` נכתב מחדש לפי הגרסה החדשה (ראו "הרחבות והגדרות האתר")
3. שומר עותק של מסד הנתונים (`database.upgrade-backup`)
4. מחליף את התיקיות בשינוי שם: הגרסה הישנה עוברת ל-`mediawiki.upgrade-old`
5. מריץ את `update.php` ‏(`maintenance/run.php update --quick`) מול מסד הנתונים, כולל הטבלאות של ההרחבות שמופעלות
6. רק אחרי שהעדכון הצליח, מוחק את הגרסה הישנה ואת עותק מסד הנתונים

אם משהו נכשל, הוויקי חוזר בדיוק למצבו הקודם: הגרסה הישנה ומסד הנתונים כפי שהיה לפני `update.php`.
אם האפליקציה נסגרה או קרסה באמצע, השדרוג מבוטל (או, אם `update.php` כבר הצליח, מושלם) בהפעלה הבאה,
לפני שאפשר להפעיל את השרתים, ומוצגת הודעה. מצב השדרוג נשמר בקובץ `mediawiki-upgrade.json` בתיקיית הנתונים.

השדרוג מסרב, בלי לשנות דבר, כש:
- הגרסה המותקנת חדשה יותר משל האפליקציה, או זהה לה (אין שדרוג לאחור)
- `LocalSettings.php` טוען הרחבה או עיצוב שאינם כלולים בגרסה החדשה (למשל Interwiki, שעבר לליבה של MediaWiki ב-1.44)
- ה-PHP שבשימוש ישן מדי לגרסה החדשה

קבצים אחרים שהוספו ידנית לתיקיית MediaWiki (מחוץ ל-`LocalSettings.php` ו-`images`) אינם מועברים לגרסה החדשה.
דרוש מקום פנוי בדיסק לגרסה החדשה ולעותק של מסד הנתונים.

## בדיקות

יש שלוש רמות של בדיקות. כולן עובדות בתיקיות זמניות ואינן נוגעות בנתונים של האפליקציה או במסד נתונים שמותקן במחשב.

| פקודה | מה נבדק | מה נדרש |
|-------|---------|---------|
| `npm test` | הלוגיקה כולה: מצב פיתוח, מסלול ההתקנה וההפעלה האמיתי מול תוכנות דמה, שדרוג ויקי מותקן והתאוששות משדרוג שנקטע, עדכון הגדרות שנכשל או נקטע, הורדות מול שרת מקומי, איתור תוכנות מותקנות, בדיקות שם המשתמש והסיסמה של המנהל, התפריט, התהליך הראשי של Electron ותצוגת הוויקי | Node.js בלבד |
| `npm run test:system` | המסלול המלא מול PHP, ‏MariaDB/MySQL ו-MediaWiki אמיתיים שמותקנים במחשב, כולל כניסה לוויקי, דף קטן שמשתמש ב-Lua, בפונקציית פרסר, בהערת שוליים, ב-TemplateStyles ובנוסחה, התאוששות מקריסה, החזרת הוויקי אחרי `update.php` שנכשל, ושדרוג אמיתי של ויקי מגרסה 1.43 לגרסה של האפליקציה | התוכנות מותקנות (אחרת הבדיקה מדולגת) |
| `npm run test:e2e` | חלון האפליקציה עצמו, דרך Playwright, במצב פיתוח: השלבים, הטופס, התפריט, והוויקי שממלא את החלון | תצוגה (בלינוקס בלי מסך: `xvfb-run -a npm run test:e2e`) |

`npm run test:all` מריץ את שלושתן, ו-`npm run coverage` מפיק דוח כיסוי בתיקיית `coverage`.

ב-`npm test` שום דבר לא יורד מהאינטרנט ושום שרת אמיתי לא רץ: במקום PHP ו-MariaDB רצות תוכנות דמה
(`test/fixtures`), ותוכנת הדמה של מסד הנתונים מדברת בפרוטוקול של MySQL, כך שהחיבור, שאילתות ההקמה
והכיבוי של האפליקציה נבדקים באמת. חלק מהבדיקות האלה מדולגות ב-Windows, שם אי אפשר להריץ את תוכנות הדמה.

להרצת `test:system` באובונטו 24.04 (שבה PHP הוא מהענף שהאפליקציה דורשת):

```bash
sudo apt install php-cli php-mysql php-intl php-mbstring php-xml mariadb-server
```

חבילת `mediawiki` של אובונטו היא מגרסה ישנה (1.39), ו-MediaWiki שנמצא במחשב משמש רק אם הוא מהענף
שב-`src/versions.js`. לכן מורידים את הגרסה שהאפליקציה עצמה מורידה (הכתובת מודפסת ב-`node scripts/mediawiki-release.js`),
פורסים אותה ומפנים אליה את `HAMICHLOL_MEDIAWIKI_DIR`. בדיקת השדרוג צריכה בנוסף את הגרסה הישנה פרוסה
ב-`HAMICHLOL_TEST_OLD_MEDIAWIKI_DIR` ואת קובץ ה-zip של הגרסה החדשה ב-`HAMICHLOL_TEST_MEDIAWIKI_ZIP`
(הוא מוגש לאפליקציה במקום ההורדה), ואחרת היא מדולגת:

```bash
eval "$(node scripts/mediawiki-release.js 1.43.11)"   # version, url, old_version, old_url
mkdir -p ~/mediawiki-releases && cd ~/mediawiki-releases
curl -fLO "$url" && curl -fLO "$old_url"
unzip -q "mediawiki-$version.zip" && tar -xzf "mediawiki-$old_version.tar.gz"
cd -
HAMICHLOL_MEDIAWIKI_DIR=~/mediawiki-releases/mediawiki-$version \
HAMICHLOL_TEST_OLD_MEDIAWIKI_DIR=~/mediawiki-releases/mediawiki-$old_version \
HAMICHLOL_TEST_MEDIAWIKI_ZIP=~/mediawiki-releases/mediawiki-$version.zip \
npm run test:system
```

ב-GitHub Actions‏ (`.github/workflows/test.yml`) רצות הבדיקות הרגילות בלינוקס, ב-Windows וב-macOS,
ובנוסף בדיקות המערכת (כולל בדיקת השדרוג) וחלון האפליקציה באובונטו 24.04. בדיקות המערכת רצות גם ב-Windows, מול PHP ו-MariaDB
שמורדים בקוד ההורדה של האפליקציה עצמה (`node scripts/download-servers.js <תיקייה>`), כמו שהמשתמשים מקבלים אותם. שם PHP ו-MariaDB מותקנים
מחבילות אובונטו, וקובצי MediaWiki (הגרסה של `src/versions.js` מאותה כתובת שהאפליקציה מורידה, והגרסה
הישנה לבדיקת השדרוג) נשמרים במטמון של GitHub Actions לפי הגרסאות, כך שהם יורדים רק כשגרסה משתנה.
גם קובץ Electron נשמר במטמון. המשתנה `HAMICHLOL_SYSTEM_TESTS_REQUIRED=1` הופך שם תוכנה חסרה לכישלון
במקום דילוג, כך שהבדיקות לא יכולות לעבור בלי לבדוק דבר.
